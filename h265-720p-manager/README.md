# H.265 / 720p 视频批量转码管理器

纯 Node.js 本地应用，通过浏览器指定源视频目录，先逐个执行 `ffprobe` 读取实际分辨率，再逐个执行用户指定的 FFmpeg 转码参数。完成后可导出命令清单和验收报告。

## 环境要求

- Windows / macOS / Linux
- Node.js **18 或更新版本**（建议 20 / 22）
- 已安装 **FFmpeg + FFprobe**，两个可执行文件都已加入 `PATH`
- 无需 `npm install`，不依赖任何第三方 npm 包

检查环境：

```sh
node -v
ffmpeg -version
ffprobe -version
```

## 启动

解压 ZIP 后，在解压出来的目录运行：

```sh
npm start
```

也可以直接 `node server.js`。

在 **同一台电脑**的浏览器打开：<http://127.0.0.1:4008>

若端口 4008 被占用，可设环境变量 `PORT` 更改。例如在 PowerShell 中：

```powershell
$env:PORT=4009
node .\server.js
```

> 为避免远程访问本地文件系统，服务**仅监听 127.0.0.1**，不支持其它电脑直接访问。程序工作时请保持 Node.js 进程运行，网页关闭不影响正在进行的后台转码。

## 典型操作

1. 输入源视频根目录绝对路径，例如 `D:\Videos`。也可点 **浏览目录** 使用本机目录导航。
2. 孪生输出目录自动设为 `D:\Videos_h265_720p`；可修改**同级目录**的名称，不支持覆盖原目录。
3. 点击 **应用目录**，再点击 **扫描视频 / ffprobe**，等待扫描完成。
4. 在目录树中查看源分辨率、目标分辨率、状态、实际转码命令，以及输出路径。可先 **导出所有命令 .txt** 审查。
5. 点击 **开始 / 继续转码**，后端单任务串行转码。可 **当前结束后暂停** 或 **立即停止**。
6. 全部完成后执行 **快速验收**；需要更严格验证可执行 **完整解码验收**（会重新解码检查所有已完成视频，消耗时间和 CPU）。
7. 导出 CSV/JSON 验收报告和命令清单。

## 固定 FFmpeg 参数

严格使用以下转码参数和排列顺序（无额外 CRF、Preset、像素格式、音频重编码参数）：

```sh
ffmpeg -i "源视频路径.mp4" -c:v libx265 -movflags +faststart -vf scale=1280:720 -c:a copy "目标路径.partial.mp4"
```

**为什么末尾是 `.partial.mp4`？** 避免突然断电或程序崩溃时，未完成的残缺文件冒充正式文件。FFmpeg 结束后，程序先用 `ffprobe` 验收临时文件，成功才重命名为 `目标路径.mp4`。该临时文件的扩展名仍然可让 FFmpeg 正确选择视频容器，转码参数顺序不变。

缩放按**实际显示宽高比**计算，限定在 **1280×720 以内**，保持比例，宽高取最接近的偶数，且**不放大**较小的视频。例如：

| 源视频 | 目标视频 |
|---|---|
| 1920×1080 | 1280×720 |
| 920×1080（竖向） | 614×720 |
| 1080×1920（竖向） | 406×720 |
| 1440×1080（4:3） | 960×720 |
| 640×360 | 640×360（不放大） |

**注意：`920×1080 → 1280×720` 不属于等比例缩放，会导致拉伸。** 如果源视频实际为 `1920×1080`，才对应 `1280×720`。

## 目录树和格式

假设源视频：

```text
D:\Videos\
├── 旅行\第一天.mp4
├── 旅行\第二天.mkv
└── 旧档案\录像.webm
```

输出目录将为：

```text
D:\Videos_h265_720p\
├── 旅行\第一天.mp4
├── 旅行\第二天.mkv
├── 旧档案\录像.webm.mkv
└── .h265-720p-state.json
```

支持扫描后缀：`mp4, mkv, mov, m4v, avi, ts, m2ts, mts, webm, wmv, flv, mpg, mpeg, 3gp, vob`。扫描不递归跟随符号链接。

- `mp4/mkv/mov`：输出默认保留原扩展名。
- `m4v` 及 WebM 等**不能稳定直接装 HEVC** 的容器：输出为 `原文件名.原扩展名.mkv`，例如 `clip.webm.mkv`，便于容纳 H.265 + 原始音频、避免同名冲突。
- `-c:a copy` 会保留 FFmpeg **默认选中的音频流**的编码，但不会自动保留所有音轨、字幕或附件；也可能因目标容器不兼容而失败，错误会写入任务记录。
- `-movflags +faststart` 对 MP4/MOV 有作用，对 MKV 通常无意义；为了保证参数固定，程序仍按要求传入。

## 中断恢复与安全措施

- 状态持久化在孪生目录根部的 `.h265-720p-state.json`（包含任务、进度、错误、开始和完成时间、输出字节数及 ffprobe 验收结果）。
- 程序自动记忆上一次源/输出目录，配置保存在程序目录 `.manager-config.json`。
- 未完成 `.partial.<扩展名>` 文件不作为结果。恢复时该任务会从头转码，**不支持从码流中间继续编码**。
- 已完成、已验收且输出存在的文件下次不会再转码。`扫描` 时会检查源文件大小和修改时间，发现源文件有变化会重建任务。
- 目标位置已有文件但与目标编码/尺寸等不符合时，任务标记为 **目标冲突**，**不会自动覆盖**。手动移走冲突文件，然后点“重置失败 / 中断 / 冲突”，可重新转码。
- 失败项可重试；`ffprobe` 无法探测的源视频需要修复源文件后重新扫描。
- 快速验收：检查输出存在、非零、HEVC 编码、分辨率、首音轨音频编码和时长（1秒或2%容差）。完整解码验收会额外逐帧解码视频流，检测视频解码错误。
- 这些验收**不对比画质**，也不保证所有字幕/音轨/元数据被保留。
- 不删除、不修改源视频；不会覆盖已经存在且无效的最终输出文件。磁盘空间不足、音频封装不兼容、源文件损坏等情况会记录为失败。

## 进度/记录导出

- `ffmpeg-commands.txt`：按相对目录分组的文件列表、每个文件的实际执行命令。
- `h265-720p-report.csv`：Excel 能直接打开的验收结果（UTF-8 BOM）。
- `h265-720p-report.json`：完整任务状态和出错日志片段。

## 测试

```sh
npm test
```

任务管理工具本身不依赖 `ffmpeg` npm 库，而是直接启动 `ffmpeg` / `ffprobe` 子进程。对含恶意内容的陌生视频请先在受限环境处理。
