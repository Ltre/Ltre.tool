## 2. 问题根因与技术判断

### [4] 未应用目录直接扫描导致服务退出

旧前端只向 `/api/scan` 发送空请求，没有提交输入框的新目录；后端调用 `void manager.scan()` 且不附带 `.catch()`。当管理器尚未初始化项目时，异步函数开始处的 `throw` 变为未处理的 Promise rejection；在 Node 默认未处理拒绝策略下，可能使服务器进程退出。

修复后扫描请求携带 `source/output`，后端按需先进行同步路径校验与配置，并给异步扫描显式兜底。非法目录返回 HTTP 400，服务继续运行；在 API 无项目时也会立即返回可理解的错误。

### [5] 历史批次混用

旧设计只有单一 `manager.project` 和上次目录配置，没有可供切换的会话索引。新设计增加 `manager-sessions.json`（运行时本地索引），按源/输出目录对绑定各自状态文件，重新打开旧任务不丢失旧扫描与转码记录。每个新会话默认建议新的同级输出目录，避免复用相同目标文件路径产生覆盖风险。

### [3] 转码参数硬编码引发验收误判

旧版无条件追加 `-c:v libx265` 和 `-vf scale=宽:高`，且 `checkOutput()` 固定要求 HEVC；仅修改命令生成会使无编码器、H.264、AV1 等合法模板被误判为失败。现将模板规范化、目标尺寸计算、命令参数与已知编码器验收联动。新任务默认不传上述可选参数；已有任务迁移时保留旧式 `libx265 + fit720`，避免无意更改历史处理意图。

### [1][2][6] 界面限制

旧主题 CSS 同时包含变量与大量硬编码深色背景，仅修改 :root 变量不足以完成亮色主题；增量提供明确的 light 覆盖。旧目录树只统计筛选列表的文件数，不含子树状态分类；现在对完整任务树做递归汇总，并把统计挂回当前筛选树。原程序没有媒体流接口，使用任意文件路径访问会有本地文件泄露风险；新增受任务目录及扫描清单双重约束的媒体服务，支持 HTTP Range 和双播放器。

## 3. 实际修改

### 任务会话与服务端稳定性

- 扩展 `Manager`：会话索引、启动恢复、历史任务列表、任务切换、批量模板和单文件覆盖。
- 重启时将旧输出目录的 `.h265-720p-state.json` 作为旧会话纳入索引；保留旧任务的参数语义。
- 目录输入未应用即可扫描；跨任务切换和参数编辑仅允许在空闲状态；运行时索引加入 Git 忽略。
- 旧目录组合会打开原会话；新批次默认另建输出目录。已有不合规目标文件不自动覆盖。

### 转码模板

- `-c:v`：留空、常用编码器快捷项及手写编码器名称；校验名称，拒绝命令注入式文本。
- `-vf scale`：留空、批量百分比、旧任务的 1280×720 等比适配；单文件额外可指定宽高。
- `-crf`：留空或 0～63 数值；留空时不添加参数；保留原有 `-movflags +faststart -c:a copy`。
- 百分比缩放按宽高同比计算，并取偶数；固定宽高模式尊重用户输入，不擅自纠正其宽高比。
- 模板变更时重新生成目标尺寸与具体命令；已完成项目改模板标记目标冲突，不覆盖旧输出。
- 验收对已知编码器核对实际 codec，保留分辨率、音频、时长、可选完整解码检查。

### 前端与视频预览

- 任务侧栏：新建、选择历史任务、完成/异常摘要，切换后更新右侧工作区。
- 批量模板区、单视频编辑弹窗；按参数条件动态显示百分比、宽高、自定义编码器控件。
- 文件夹折叠行显示其整个子树「已完成、异常/中断、转码中、总数」，不受筛选影响。
- 已完成文件可打开原视频与结果视频：桌面左右布局，窄视口上下布局；总容器限制在视口，内部媒体可缩放。
- `GET/HEAD /api/video`：支持单 Range、206/416、Seek；仅可读取当前会话登记的源视频或已完成输出，真实路径不得越过对应根目录；跨站媒体请求被拒绝。
- 增加亮色、暗色、跟随系统主题选择，偏好保存于本机浏览器。默认亮色。

## 5. 兼容性、限制与后续事项

- 问题单 `3.3、支持` 没有参数名称或行为定义，暂不擅自实现；需补齐需求后另行开发。
- 单文件指定宽高允许非等比变化；若需保证等比，请自行输入相应比例。
- 百分比偶数取整会出现不超过约 1 像素/方向的尺寸偏差；特殊大尺寸或编码器不支持的配置可能导致 FFmpeg 失败，错误仍按文件记录。
- 浏览器预览不等于验收，部分 HEVC/MKV 文件可能无法原生播放；以 FFprobe/完整解码结果为准。
- 既有输出文件不会被修改；修改参数后需要手动移走旧目标文件，或在另一个会话使用新的输出目录。
