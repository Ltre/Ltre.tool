# 3FUI（FFmpegFreeUI）孪生目录树输出功能技术说明

> **核查范围：** FFmpegFreeUI v6 源代码，GitHub 默认分支提交 [`787fb527`](https://github.com/Lake1059/FFmpegFreeUI/commit/787fb527b2a1e4cd247899e3f295b6b2a4e836cc)（提交时间：2026-11-07）。  
> **文档用途：** 说明 3FUI 如何将批量处理的媒体文件输出到另一根目录，同时保留源目录下的相对文件夹层级；记录配置方法、核心实现和适用边界。  
> **核查方式：** 阅读对应的 UI、编码队列、预设数据及预设持久化源代码；未在 Windows 桌面环境实际操作或执行批量转码。

## 1. 结论

**3FUI v6 已支持以“自定义输出目录 + 保留子文件夹结构起始点”的组合方式，重建批量处理文件的相对子目录。** 这可以用于生成类似“孪生目录树”的结果目录。

这项功能**不是**自动将源目录完整复制到另一个位置，也**不是**自动创建一个同级且按规则命名的孪生输出根目录：用户需要指定输出目录，以及用来计算相对路径的源目录起始点。实际被处理的文件会按输出文件命名规则生成到对应目录；没有被加入任务的非媒体文件和空文件夹，不能据此认为会被同步复制。

### 1.1 相关需求讨论：GitHub Issue #132

3FUI 官方仓库曾有一篇直接讨论本功能的需求帖：**[[Feature]：批量转换时输出目录保留源目录中各子级目录结构](https://github.com/Lake1059/FFmpegFreeUI/issues/132)**（Issue #132）。它是这项功能的**相关讨论记录**，而非单独的代码实现证明。

- **提出时间：** 2026-03-07。发帖人表示，当时批量转码的结果只能集中放在单一输出目录，导致原有子目录结构丢失，也不方便把未转码的其他文件放回相应层级。
- **当时的替代做法：** 借助 Shell 脚本计算相对路径、创建对应输出子目录，但这样无法继续使用 3FUI 界面集中操作和监控。
- **讨论补充：** 有评论提到 HandBrake 的相关目录保留设置；这属于其他软件的参考示例，不代表 3FUI 当时已支持相同功能。
- **议题状态：** 2026-06-30 以 `completed` 理由关闭。该状态表明需求讨论已被关闭，但具体功能及行为仍应以本文件核查的 v6 源码为依据。

这篇讨论说明了“保留相对目录结构”的实际使用诉求；下文第 2～6 节记录的是后续版本中已核查的配置入口与实现行为。

## 2. 配置入口与字段

在 3FUI v6 的**参数面板 → 输出文件设置**中，相关配置如下。

| 界面字段 | 作用 | 典型值 |
| --- | --- | --- |
| **输出目录（输出位置）** | 指定转码结果的目标根目录 | `D:\Videos_h265` |
| **保留子文件夹结构起始点** | 指定源目录中用于计算相对文件夹层级的起点 | `D:\Videos` |
| **输出后缀／容器** | 决定输出文件扩展名 | `.mp4`、`.mkv` 等 |
| **自动命名方式** | 决定是否对输出文件名追加时间戳或序号等 | 按实际需求设置 |

“保留子文件夹结构起始点”输入框在代码中对应 `MCB_保留子文件夹结构起始点`，界面说明为“要保留子文件夹结构时设置起始点（从根目录开始）右键点击清空”。输出目录选择框对应 `MCB_输出位置`。两者均支持选择文件夹。

**前提条件：**

- 使用**有效的自定义输出目录**，而不是“输出到原目录”。
- 自定义输出目录必须已经存在；不存在时不会作为有效自定义输出位置使用。
- 保留结构的起始点必须是已经存在的目录；无效路径在界面或参数保存时会被清空。
- 要保留的输入文件须位于起始点目录之下（或位于起始点本身），才能计算出正确的相对目录。

### 2.1 在 3FUI 软件中实际如何操作（Windows，v6）

以下按照“源视频保留不动，转码结果输出到源目录同级的孪生目录，并保留源目录下的所有**已转码视频的相对文件夹层级**”这一目标操作。示例源目录为 `D:\Videos`，目标目录为 `D:\Videos_h265`。

1. **先在 Windows 中准备两个目录。** 确认 `D:\Videos` 存在并包含待处理视频；另行建立一个空的 `D:\Videos_h265`。3FUI 对自定义输出根目录进行存在性检查，不能仅填写尚未创建的目标路径。
2. **打开 3FUI 的「参数面板」→「输出文件设置」。** 在“输出模式”保持 **「常规模式：正常附加输出文件参数」**，不要使用“不附加输出文件参数”或“附加丢弃输出文件参数”等特殊模式。
3. **设置孪生输出根目录。** 在**「输出目录」**（源码控件 `MCB_输出位置`）中选择 **「浏览 ...」**，指定已存在的 `D:\Videos_h265`。不要选 **「输出到原目录」**，否则不会产生独立的孪生输出根目录。
4. **设置要保留目录层级的源起始点。** 在**「保留子文件夹结构起始点」**（源码控件 `MCB_保留子文件夹结构起始点`）中选择 **「浏览 ...」**，指定 `D:\Videos`。这个位置应当是**源根目录本身**，而不是 `D:\Videos\电视剧\第一季` 等更深的子文件夹，否则源根目录与该起始点之间的层级不会被保留。该输入框也支持右键清空。
5. **确认输出后缀和自动命名方式。** 按需要设置输出容器（如 `.mp4`、`.mkv`）。3FUI 的默认自动命名方式是追加递增时间戳；如果希望输出文件名尽量沿用源文件主文件名，可选择 **「不使用自动命名」**，并检查开头文本、替代文件名、结尾文本等命名设置。**保留文件夹层级不等于保留文件名**，也不保证后缀与源文件相同。
6. **把源目录下的视频加入待处理列表。** 进入主界面的**「准备文件」**，点击 **「添加文件夹及子目录」**，选择 `D:\Videos`。此操作会递归枚举文件；由于源码中的枚举不限于视频后缀，**应在待处理列表中检查并移除不需要处理的文件**。也可以通过「添加文件」单独选择部分视频。
7. **加入编码队列。** 在「准备文件」列表核对完成后，点击 **「加入编码队列」**。软件会根据当前参数面板生成队列任务并跳转到编码队列页面；在队列中检查输出路径，确认类似 `D:\Videos\电视剧\第一季\01.mp4` 的源文件，其输出位置位于 `D:\Videos_h265\电视剧\第一季\` 下。
8. **开始转码并查看结果。** 按编码队列中的开始操作执行（是否自动开始还受到软件的“是否自动开始任务”设置影响）。完成后在 Windows 资源管理器打开 `D:\Videos_h265`，检查相对目录层级和文件内容；原源目录仍用来保留源视频。

**需要核对的两个关键配置：**

```text
3FUI → 参数面板 → 输出文件设置
输出目录：                  D:\Videos_h265
保留子文件夹结构起始点：    D:\Videos
输出模式：                  常规模式：正常附加输出文件参数
```

> 注意：设置“保留子文件夹结构起始点”**不会单独触发文件扫描或复制**；它只影响加入编码队列的输入文件如何计算输出路径。未加入队列的文件、空目录不会因为这项设置自动同步。如果准备文件来自 `D:\Videos` 以外的其他目录，原有层级也不保证能按预期保留。

### 2.2 怎样确认配置已经生效

可以先挑选一个位于**至少两层子文件夹中**的短视频加入队列，例如 `D:\Videos\电视剧\第一季\01.mp4`。检查任务生成的输出路径是否包含 `电视剧\第一季`，而不是直接落在 `D:\Videos_h265` 根目录。若层级不对，优先核对“输出目录”是否有效，以及“保留子文件夹结构起始点”是否误选成了子目录。

这一检查可在正式批量执行前发现配置错误。上述操作步骤依据 v6 界面、队列源码还原，**不是实际 Windows GUI 操作或转码验收记录**。

## 3. 孪生目录树示例

假设源目录为：

```text
D:\Videos\
├─ 电视剧\
│  └─ 第一季\
│     ├─ 01.mp4
│     └─ 02.mp4
├─ 电影\
│  └─ A.mkv
└─ 说明.txt
```

在 3FUI 中设置：

```text
输出目录：                D:\Videos_h265
保留子文件夹结构起始点： D:\Videos
```

将对应视频加入队列并按合适的输出容器／命名参数执行后，可以形成：

```text
D:\Videos_h265\
├─ 电视剧\
│  └─ 第一季\
│     ├─ 01.mp4
│     └─ 02.mp4
└─ 电影\
   └─ A.mkv
```

> 上述文件扩展名与源文件相同仅为示意。实际输出名称和扩展名由 3FUI 的**输出容器、命名方式及所选参数**决定。`说明.txt` 不会仅因为启用了保留结构选项就自动复制过去。

例如对源文件：

```text
输入：D:\Videos\电视剧\第一季\01.mp4
```

程序计算的是**输入文件所在文件夹**相对于起始点的路径：

```text
输入文件所在目录：D:\Videos\电视剧\第一季
起始点：          D:\Videos
相对文件夹：      电视剧\第一季
目标文件夹：      D:\Videos_h265\电视剧\第一季
```

输出文件名随后拼接到该目标文件夹中。

## 4. 源码中的核心逻辑

### 4.1 输出路径的构成

主要实现位于：

`FFmpegFreeUI/功能/编码队列_v6.vb`

相关流程：

1. 从输入文件路径取得其所在目录。
2. 判断是否使用有效自定义输出目录；不使用时，输出目录沿用输入文件所在目录。
3. 在指定了保留结构起始点时，计算“输入所在目录相对起始点”的子路径。
4. 将相对子路径拼接到自定义输出根目录。
5. 在需要实际生成目录时调用 `Directory.CreateDirectory()`。
6. 最后拼接由输出命名规则生成的文件名和容器扩展名，并应用文件名冲突处理规则。

简化后的**说明性伪代码**（不是可直接运行的原项目代码）：

```text
sourceFolder = dirname(inputFile)
outputFolder = configuredOutputFolder

if customOutputFolderIsValid:
    relativeFolder = relativePath(sourceRoot, sourceFolder)
    if relativeFolder is valid:
        outputFolder = join(configuredOutputFolder, relativeFolder)
    createDirectoryIfNeeded(outputFolder)
else:
    outputFolder = sourceFolder

outputFile = join(outputFolder, outputName + outputExtension)
```

对应原项目函数包括：

- `计算输出位置_v6`：生成最终输出路径。
- `计算输出目录`：选择输出根目录，并拼接保留的相对子目录。
- `计算保留子文件夹结构相对目录`：根据起始点计算保留的子目录。
- `计算本机相对目录`：执行路径归属检查，并借助 `.NET Path.GetRelativePath()` 计算相对路径。
- `路径位于目录内`、`清理相对子目录`：辅助检查相对路径，避免直接接受 `..` 向上跳转等不合法路径。

### 4.2 目录何时创建

`计算输出位置_v6` 含有 `创建输出目录` 参数；实际创建时才会触发 `Directory.CreateDirectory()`。因此，**生成或预览一条输出路径**与**在磁盘上创建该目录**不是完全相同的操作。

### 4.3 和普通自定义输出目录的区别

| 设置方式 | 输出行为 |
| --- | --- |
| “输出到原目录” | 输出至每个输入文件原本所在的文件夹；不生成独立孪生根目录 |
| 只设置 `D:\Videos_h265`，不设置保留起始点 | 视频输出目录通常集中在 `D:\Videos_h265`，不会自动保留源目录下的多级结构 |
| 同时设置输出目录 `D:\Videos_h265` 与起始点 `D:\Videos` | 对起始点之下的输入文件，按照相对文件夹路径重建输出层级 |

## 5. 适用边界与注意事项

### 5.1 输入不在起始点目录下

如果输入文件的目录不属于指定起始点，源码中的本机相对目录计算会返回空值。在正常模式下，**不会凭空把不相关的目录层级迁移到输出根目录**；这类文件可能直接输出到指定输出根目录。因此，批量处理多个不相干源目录时，不能假设使用一个起始点就能同时保持全部目录层级。

### 5.2 起始点等于输入文件所在目录

相对路径为 `.`／空时，不会附加子目录；文件直接输出到所设输出根目录。这是正常的根目录文件映射行为。

### 5.3 输出目录无效

界面保存参数时会验证输出位置是否存在。输出位置无效时，会清空自定义输出位置及“保留子文件夹结构起始点”，并按默认输出目录逻辑处理。因此不能只填写一个尚未建立的输出根目录，并认定程序会自动将其作为有效孪生根目录。

### 5.4 输出目录与命名方式是两回事

“保留子文件夹结构”保证的是**输出文件夹的相对层级**；并不保证输出文件的名称、扩展名、文件数量和源目录完全一致。输出文件名仍受容器后缀、自动命名和文件名冲突处理等机制影响。

### 5.5 是否复制未转码文件、空目录

已核查的实现以**加入编码队列的输入文件**为单位生成输出路径，没有证据表明该选项还会递归复制全部普通文件或空目录。不能将它等同于完整目录同步软件。

### 5.6 特殊输出模式

`计算输出位置_v6` 仅在“正常使用输出文件参数”的模式下继续生成这一常规输出路径。特殊模式（如不附加输出参数或声明丢弃输出）不能直接按本节的输出路径行为推断。

## 6. 预设保存与跨机器行为

该功能相关的预设字段包括：

```text
输出位置
输出位置_保留子文件夹结构起始点
计算机名称
运行时使用输出位置
```

- 运行时设置有效目录，界面会将目录信息写入当前预设数据。
- 将预设保存到文件时，输出位置和起始点属于**额外保存输出位置**相关内容；不保存这些信息时，保存逻辑会清空两个路径字段。
- 预设读取时，会检查保存时的机器名称与当前机器是否匹配，以及目录是否仍然存在；不满足要求时，预设中的输出位置可能不被采用。
- 3FUI 的 Agent 参数工具说明：调用 `save_parameter_preset` 若要持久化输出位置和起始点，应指定 `save_output_location=true`。

因此，“某次运行已配置好孪生目录映射”和“今后重新加载预设仍保留这些目录配置”是两个需要分别确认的行为。

## 7. 与 ffmpeg-batch 孪生目录功能的对应关系

| 能力 | 3FUI v6 | 当前 `ffmpeg-batch` 的设计 |
| --- | --- | --- |
| 将转码结果输出至另一根目录 | 支持配置有效自定义输出位置 | 支持指定独立输出根目录 |
| 保留源文件夹的相对层级 | 支持，需设置结构起始点 | 以源根目录为基准生成对应目录树 |
| 自动推荐孪生输出根目录名称 | 本次核查未发现同等的自动命名规则 | 根据源目录建议同级输出目录名称 |
| 批量输出文件名 | 取决于 3FUI 容器与自动命名策略 | 取决于项目现有输出文件命名规则 |
| 是否复制非转码文件或空目录 | 不能据此认定支持 | 孪生输出针对视频转码结果，不等同于完整文件夹复制 |

这里的比较仅针对**目录输出规则**，不对两套工具的整体任务管理、转码性能或其他能力作优劣判断。
