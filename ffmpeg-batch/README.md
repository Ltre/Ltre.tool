# FFmpeg 批量转码管理器

无需 npm 依赖的 Node.js 本地工具：递归扫描、逐个 ffprobe、可定制 FFmpeg 转码参数、断点恢复、验收、历史任务和源/结果视频对比。

## 运行

需要 **Node.js >=18**、系统已安装 **ffmpeg** 和 **ffprobe** 并加入 PATH。Windows/macOS/Linux 均可使用。

```sh
cd ffmpeg-batch
npm start
```

打开 <http://127.0.0.1:4008>。进程只监听回环地址，外部网络不能直接访问。可设置 `PORT` 更改端口。

## 任务（会话）

- 左侧「新建任务」建立新批次；各任务独立保存扫描清单、模板、状态、日志和验收结果。点击历史任务可以切换检视、恢复处理。
- **Q1-F 删除历史任务**：侧栏每条任务提供删除按钮，需确认后移除该会话的索引及状态文件；不删除源视频、转码结果或目录。正在扫描、转码或验收的目标任务禁止删除，其他会话不受影响。
- **Q1-C 新任务工作区**：新建时真正克隆一整套「01 项目目录」「02 批量模板」「03 处理队列」「04 视频目录树」「结果与验收报告」DOM，全部展示空白初始状态，并在配置之前禁用结果导出。该工作区不会复用旧任务的面板或统计数据；输入源目录后会建议带唯一后缀的同级输出路径。
- 每个已打开过的会话拥有自己的页面 DOM 实例；切换仅挂载对应工作区，保留原先未保存的输入框值、文件展开/目录折叠状态等。新任务应用目录前仅存在于当前页面，未配置的草稿不会写入历史任务注册表；切换到历史任务或再次点击新建会舍弃未配置草稿。
- **允许不同任务并行执行**：任务 A 扫描、转码或验收期间仍可新建/切换任务 B 并启动任务 B；每个任务拥有自己的工作状态、FFmpeg 子进程、暂停/停止/验收，互不影响。同一个任务内部仍逐文件串行转码。侧栏显示各任务的运行状态。
- 扫描时直接填写新的源/输出目录，**无需预先点击「应用目录」**；后端会先应用目录再扫描，无效路径返回错误，不会导致服务退出。
- 新任务会建议带唯一后缀的同级输出目录。**同一个输出目录不能作为多次任务的独立输出空间**，避免历史结果冲突；若重新填写已存在的源/输出组合，会重新打开原任务。
- 旧版 `.h265-720p-state.json` 在首次打开时自动纳入历史任务索引，并继续采用旧默认参数。
- 任务索引存于程序目录 **`.data/.manager-sessions.json`**，最近使用目录保存在 **`.data/.manager-config.json`**。首次启动会将旧位置仍存在的文件迁移至 `.data/`，已存在的目标文件不被覆盖。
- `.data/` 已加入 `.gitignore`，由程序首次启动时自动创建，不会将用户的本机路径与会话索引提交到 Git。**如果 Git 更新过程中旧版被跟踪的 `.manager-config.json` 已被删除，程序无法从不存在的源文件迁移**；升级前有需要可备份该配置。各任务的完整状态仍存于其输出目录的 `.h265-720p-state.json`，也应备份。
- 多任务并行时必须使用不同的输出目录（包含实际指向同一目录的符号链接别名），以避免文件覆盖。不要在进程运行时手动修改状态文件。

## 批量转码模板

每个**新任务**默认不显式设置 `-c:v`、`-vf scale` 和 `-crf`，由 FFmpeg 根据目标封装格式决定默认编码器/尺寸。可以逐项选用：

| 参数 | 批量模板 | 单文件模板 |
|---|---|---|
| `-c:v` | 留空、`copy`（原视频流直接复制）、libx265、libx264、AV1、NVENC 或手写 FFmpeg 编码器名称 | 同左 |
| `-vf scale` | 留空、百分比、分数、以短边 N px 缩放、旧 720p 模式 | 同左，另允许单文件明确指定宽和高 |
| `-crf` | 留空或 0～63 数值 | 同左 |

- **分数模式**：输入 `分子/分母`，例如 `720/1080` 或 `2/3`。程序用 `BigInt` 整数运算约分并计算 `宽×分子/分母`、`高×分子/分母`，中途不把 `2/3` 转换为小数；`1920×1080` 对应 `1280×720`。分子/分母必须为正整数，分母不可为零。最终目标尺寸才按最接近的偶数取整（半值向上取整），保证两种等价分数生成相同像素尺寸。
- **短边 N px 模式**：N 为 2～16384 的整数，目标短边保持为 N，另一边按 `长边×N/原短边` 用整数分数精确计算，再取最接近的偶数。N=720 时，`1920×1080 → 1280×720`、`1080×1920 → 720×1280`。**若源视频的短边恰好等于 N，则保留原始宽高、完全省略 `-vf scale`，包括长边是奇数的情况。** 若 N 为奇数，部分常见编码器可能无法编码，程序不会私自更改指定短边。
- 百分比缩放会把宽高各自乘以比例并四舍五入到偶数；像素取整可能引入极小的长宽比偏差。新分数模式仅避免中间计算的循环小数误差，不代表任意比例的最终宽高都能恰好是整数。
- 明确填写宽高的单文件模式**按指定尺寸输出**，不会自动保持宽高比。请填写等比例的目标尺寸。
- 选择 `-c:v copy` 时不重新编码视频，不可使用缩放滤镜或 CRF；表单会禁用这两个选项，后端也会校验。选择某些硬件编码器需要对应设备/FFmpeg 编译支持。
- 其余固定参数仍为 `-movflags +faststart -c:a copy`，只复制 FFmpeg 默认选择的音轨，并不保证保留所有字幕/音轨。
- 旧任务迁移时仍按 `libx265 + 720p` 转码；已有输出文件不因升级被强制重转。修改已完成文件的模板会标记冲突，不自动覆盖旧文件；请将旧输出移走后重试，或使用新任务的新输出目录。

示例：

```sh
ffmpeg -i '/path/in.mp4' -c:v libx265 -movflags +faststart -vf scale=1280:720 -crf 26 -c:a copy '/path/out.partial.mp4'
```

实际命令可在每个视频详情中查看、复制，也可按目录层级导出。

## 目录树、预览与验收

- 目录折叠状态仍显示该目录**整个子树**的「已完成 / 异常及中断 / 转码中 / 总数」。即使启用了文件筛选，统计仍按全部视频计算。处理队列顶部另有位于「转码完成」右侧的「转码中」统计。
- 已启用单文件覆盖参数的视频行有醒目的「独立参数」标记，展开与否、转码状态如何都不影响标记显示。
- **输出体积变化（Q1-E／Q1-F）**：验收完成且大小有效时，`.file-head` 直接显示带符号的体积变化率和增减量，例如棕色 `－47.1%|-13.33M`、红色 `＋20.0%|+7.80M`，相同大小显示中性色；M 按 MiB 计算，较小变化使用 K/B。保留「输出比原文件大」筛选与队列统计、文件详情、CSV/JSON 和命令报告，历史完成任务无需重新转码即可计算。
- **FFmpeg 日志定位**：首次展开有日志的视频详情时，日志框自动滚动到最后一行；如果用户主动向上查看旧日志，后台周期性刷新目录树不会强制跳回底部。重新折叠再展开会默认显示最新日志。
- 展开已完成视频可点击「原视频 / 结果视频对比」；宽屏左右排列，窄屏上下排列，播放器不超出视口。播放支持 HTTP Range/Seek；会话 ID 绑定媒体链接，切换任务不会使播放器后续的 Range 请求指向别的任务。只能读取已登记于所选任务的视频，且路径必须位于对应源/输出目录。
- **双视频同步对比**：对比窗口底栏增加最左侧「上一个」和最右侧「下一个」按钮，按相对路径顺序切换可对比的已完成视频，优先采用当前筛选结果；原来的 `−8`、`−2`、`▶ / ⏸`、`+2`、`+8` 五个同步播放控制仍保留。拖动任一原生进度条时，会同步另一播放器的相同播放时间；播放中的明显漂移也会自动修正。
- **可观看性验收（Q1-H）**：在任务空闲且存在已完成视频时，点击「验收可观看性」。它会遍历当前任务所有已完成视频，不受目录树展开状态和筛选条件影响；每个视频分 10 个均匀检测位置，左右播放器分别定位，每个位置自然播放 1.2 秒，等待 seek 后实际呈现的解码帧，再按媒体时间采集 3 帧比较。验收遮罩提供暂停、继续和停止；结束后显示通过/失败/无法判定/未完成报告，并支持导出 JSON；每个视频可直接打开原有双视频对比，关闭报告后也可从当前任务的可观看性验收记录重新打开。自动画面比较使用局部 SSIM、亮度和色彩差异，属于异常筛查，不等同于人工主观画质审查；原视频无法读取时会标记无法判定，结果视频无法在当前浏览器解码时会标记失败。
- **快捷键**：弹窗打开期间，`←`/`→` 单击同步后退/前进 2 秒；相同方向键在 280 ms 内快速连击，总共后退/前进 8 秒，不叠加单击的 2 秒。首击稍作延迟，以便判断是否为双击；关闭弹窗会取消未执行的按键。组合键、长按重复和输入框内的方向键不触发控制。
- **浏览器不一定支持 HEVC、MKV、部分 MOV 音视频格式**。如果任一播放器无法播放，统一播放会提示失败并停止双方；无法播放不等于源视频或转码结果已损坏，仍应以 FFprobe/完整解码验收为准。
- 转码中使用 `*.partial.<扩展名>` 临时输出，完成后先 ffprobe 验收，再原子改名。可暂停队列、终止当前 FFmpeg、重试失败项。
- 快速验收检查非空、预期编码（对于已知编码器）、尺寸、音频编码与时长；完整验收额外逐帧解码。**不检测主观画质**。
- 不覆盖已有且未通过验收的目标文件，不删除或修改原视频。

## Q1-F：多模板管理、组合筛选与操作说明

- 一个任务可创建多个具名批量模板，只有一个模板被指定为全局模板；其余为局部模板。可通过模板下拉框切换编辑、新增模板、修改名称与参数、将选中的模板设为全局或删除未使用的模板。
- 单文件模板改为三个互斥的 Radio：`使用当前任务的全局模板`、`使用其它批量模板（局部作用域）`（选择后启用模板下拉框）、`当前文件独立设置参数`（选择后启用 `#item-fields`）。全局模板变更不影响已经独立设置参数或绑定局部模板的视频。
- 局部模板被提升为全局时，系统为原来引用它的文件保留一份局部副本，避免后续全局修改影响已有局部绑定。局部模板被占用时不可直接删除，当前全局模板也不可直接删除。
- 旧状态文件自动迁移为一个「默认模板」；旧单文件 `override` 保持为独立参数，未单独设置的文件继承全局模板。模板参数变化时只重算受影响的文件；已完成文件如配置发生变化，会标记冲突且不覆盖已有输出。
- 视频目录树筛选可以组合使用：状态、文件名或相对路径关键字（不区分大小写）、体积变化率区间（如 `-5%` ～ `+50%`，包含端点）和分辨率变化（缩小、不变、放大）。
- 体积变化率按 `(输出文件字节数 - 原文件字节数) / 原文件字节数 × 100%` 计算，仅对有效的已完成视频应用。分辨率变化按原始与目标的像素总数比较；待处理视频使用计划目标尺寸，已完成视频使用通过验收的目标尺寸。

## 检查和测试

```sh
npm run check:syntax

npm run test:integration
```

测试使用 Node 内置 `node:test`，由 `test/run-tests.js` 为测试创建并在结束时清理**独立临时数据目录**，避免污染实际用户的 `.data`。新增工作区克隆状态、同步视频控制器和键盘时间窗测试；检测到 Chromium/Chrome 与 Node.js 22+ 时会运行真实浏览器交互回归测试，否则明确跳过该项。集成测试需要本机 ffmpeg/ffprobe：自动生成短视频，实际转码、探测和走 HTTP Range 接口；还覆盖分数/短边尺寸、并行会话隔离、运行中切换及配置迁移。不安装第三方测试框架。GitHub Actions 也会在 `dev/2611-s1-Q1` 的相关提交上运行语法检查与测试。
